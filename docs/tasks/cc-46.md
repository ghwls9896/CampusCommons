# CC-46 실제 계정 도서관 로비 인계

담당은 HIGHCHOI이며 브랜치는 `codex/cc-46-account-lobby`다. 클라이언트 구현은 `bb5d07e`, 에디터 회귀 검사는 `30d2056`이다. [이슈 #46](https://github.com/ghwls9896/CampusCommons/issues/46) · [PR #47](https://github.com/ghwls9896/CampusCommons/pull/47)

## 구현

로그인한 사용자가 도서관에 있으면 기존 게임 계정으로 공용 로비에 접속한다. 원격 참가자의 닉네임과 움직임, 개인방 이동·퇴장, 만원 대기와 연결 복구를 처리한다. 계정별 연결 하나를 유지하며 중복 로그인 시 새 창이 기존 자리를 이어받는다. 공유 씬, 공통 Player, 서버 설정 변경은 없다. [게임 동작과 검증 방법](../multiplayer/UNITY_LOBBY.md)

## 실제 실행한 검사

| 환경 | 결과 |
|---|---|
| Unity 6000.4.5f1 Play Mode, 실제 도서관과 #45 로컬 Uvicorn, 독립 WebSocket 상대 | 양방향 이동·정지, 퀴즈방 출입, 닉네임 저장, 중복 접속, 개인방에서 세션 만료 후 재로그인, 일시적 503 복구, 최종 로그아웃·명단 제거 통과. 8명이 찬 상태에서 만원 안내 후 빈자리 자동 입장도 통과. 계정 로그인과 서버의 프로필 응답은 테스트 데이터로 대체했다. |
| 같은 Unity 버전에서 LobbyAvatarVerification.Run | Sunbox 설치와 공개 기본 도형 구성에서 각각 통과. 같은 이름의 서로 다른 계정, 빈 초기 위치, 슬롯 배치, 원격 외형의 카메라·충돌체 분리 확인. 일부 실행에서 플레이 직전 UnityEditor.Search.SearchDatabase 색인 예외가 한 번 발생했고 검사는 종료 코드 0으로 완료됐다. |
| 계정 세션, 기존 서버·협업 도구 | Unity 번들 Mono에서 운영·루프백 빌드 기호 각각 50개 통과. 클라이언트 PR 기준 backend 테스트 52개와 팀 도구 테스트 16개 통과. |
| macOS arm64 실제 계정용 실행본 | 로그인 창 2개를 열고 초기 계정 설정 및 로그인 전 상태를 확인했다. 같은 Mac의 #45 서버가 인증 없는 연결을 4401로 닫았고 기존 Supabase Auth 상태 확인은 200이었다. 실제 계정 두 개의 로그인 후 플레이는 사람이 확인할 단계다. |

## 통합과 배포

1. ghwls9896가 선행 서버 PR #45를 검토·통합한다. 기존 Render 서비스의 계정 설정을 확인하고 서버 배포를 완료한다. 작업 시점의 공개 WebSocket 주소는 HTTP 404였다. [서버 PR #45](https://github.com/ghwls9896/CampusCommons/pull/45)
2. ghwls9896가 클라이언트 PR #47을 검토·통합한다. 일반 데스크톱 빌드는 운영 WSS를, Mac 두 창 시연용 빌드는 루프백을 사용한다.
3. 서로 다른 실제 계정 두 개로 도서관 인원 2/8, 상대 닉네임·이동 및 퇴장을 확인한다. 운영 주소에서의 두 기기 시연과 Windows 플레이 검증은 남아 있다. 공통 파일 점유는 없다.

## 이름표 후속 변경

HIGHCHOI가 실제 두 계정으로 같은 Mac의 로비에서 만나는 동작을 확인했다. 상대 머리 위의 닉네임·레벨은 자기 캐릭터와 같은 AccountView의 두 줄로 그린다. 서버가 레벨을 보내지 않는 이전 버전에서는 닉네임을 표시한다.
