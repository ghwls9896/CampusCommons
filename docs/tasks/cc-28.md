# Windows 통합 배포 첫 실행 수정

- 담당: ghwls9896 / #28 / Draft PR #29. #23 브랜치를 대상으로 하는 후속 수정입니다.
- Windows 로그인/웹캠 화면 글꼴을 프로젝트 내 글꼴로 바꾸고, 압축 해제 경로를 짧게 유지하며 전체 해시 충돌을 검사합니다. 긴 사용자 경로의 모든 경우를 보장하지는 않습니다.
- Unity Windows GUI 프로세스 종료와 종료 코드를 기다리도록 배포 스크립트를 수정했습니다. `Tools/distribution/tests/build-windows-process.ps1`에서 공백이 있는 경로, 성공 및 실패 전달을 모의 실행으로 확인했습니다.
- Unity 6000.4.5f1 Windows 빌드 성공, 실행 파일의 로그인 글자 표시 확인. 이전 동일 변경 진단 통합 빌드에서 실제 패키지 설치 및 로그인/로비/아바타/탈출맵 표시 확인.
- 사용자가 새 Windows 시험판에서 로그인 후 퀴즈까지 정상이라고 확인했습니다. 카메라는 이 PC에 없어 웹캠 실기기 검증을 하지 못했습니다. Windows의 더 긴 사용자 경로, macOS에서의 변경 동작은 미검증입니다.
- 최종 합본과 #23 반영은 담당자 검토가 필요합니다. 수정 중인 공유 씬/프리팹·Player·패키지 설정 없음. 개인 연결 설정 및 실행 패키지는 커밋하지 않았습니다.

## 2026-11-13 통합 전 리뷰 보완

- 공유 Resources 글꼴을 사용하는 두 웹캠 화면에서 `Destroy(font)`를 제거했습니다. Unity Play Mode에서 두 컴포넌트를 종료하면 발생하던 `Destroying assets is not permitted`를 재현한 뒤 같은 검사에서 해결을 확인했습니다.
- 설치 테스트를 16자리 디렉터리 규칙에 맞추고, 전체 SHA256 ready 마커 보존 및 접두사 충돌 시 기존 파일 보존 검사를 추가했습니다. 취소/복구/동시 설치를 포함한 36개 검사 통과.
- macOS Unity 6000.4.5f1: `WindowsDistributionChecks.Run` → `SHARED_FONT_LIFETIME_PASS`, `LocalIntegrationAudit.Quiz` → `PDF_QUIZ_ROOM_PASS` (로그인은 테스트 응답). 배포 패키지 Python 검사 5개 통과.
- 편집기 시작 시 Unity Search 인덱서 예외가 기록됐으나 게임 스크립트 컴파일 오류는 없었으며 위 Play Mode 검사가 완료됐습니다. 이번 Mac 검사는 Windows 실기기 카메라 검증을 대신하지 않습니다.
- 수정 중 공유 씬/Player/ProjectSettings 없음. HIGHCHOI 사람 승인 후 #23으로 병합합니다.
