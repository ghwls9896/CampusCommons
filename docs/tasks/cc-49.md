# 두 좌석 퀴즈룸 인계

HIGHCHOI가 기능 커밋 `e7858e5`에서 Unity 퀴즈룸을 두 좌석의 실제 착석, 대기, 개인 PDF 선택, 풀이 및 결과 화면과 연결했다. 내 캐릭터와 상대에게 같은 머리 위 닉네임·레벨을 그리는 선행 클라이언트는 #47의 `58d3f12`다. [이슈 #49](https://github.com/ghwls9896/CampusCommons/issues/49) · [PR #51](https://github.com/ghwls9896/CampusCommons/pull/51)

| 확인 환경 | 결과 |
|---|---|
| Unity 6000.4.5f1 에디터 두 개, 같은 도서관, 같은 로컬 FastAPI | 첫 착석 대기, 서로 다른 좌석·3쪽/4쪽 개인 PDF, Lv.2와 Lv.8에서 공통 Lv.5, 서로 다른 문제, 단답형 15초 초과 시 저장 답 채점, 두 창의 결과 30/30·3/3 및 15/30·1/3, 개인 해설, 기립·퇴실을 확인했다. 로그인·Gemini 응답은 테스트 데이터였다. |
| 같은 Unity 버전의 기존 검사 | QuizRoomTest.Run, IntegratedQuizFlowTest.Run, DistributionBuild.CheckConfigurationGate(6개) 통과. |
| 머리 위 표시 | Sunbox와 기본 아바타 모두 이름·레벨 갱신, 레벨 없는 이전 서버 호환, 카메라 밖 숨김 회귀 검사 통과. |
| Mac 실제 실행본 | Apple Silicon, macOS 15용 팩에 웹캠 런타임을 포함해 빌드·서명 확인. 두 실제 로그인 화면, 포트 충돌과 무인증 좌석 거부 확인. 새 2인 경기에서 실제 Gemini 호출, Windows 실기기, 웹캠 실카메라 확인은 남아 있다. |

공유 Player·씬·프리팹 변경은 없다. 기존 배포 훅은 2인 접속에 쓰이지 않는 단독 퀴즈 토큰을 요구하지 않도록 조정했다. ghwls9896가 선행 #47을 통합한 뒤 자식 브랜치에 최신 main을 병합하고 base를 main으로 조정한다. #50 서버 배포 뒤 일반 빌드로 두 기기 확인을 진행한다. [플레이·배포 설정](../multiplayer/QUIZ_PLAY.md)
