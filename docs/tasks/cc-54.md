# CC-54 통합 인계

HIGHCHOI가 두 게임 창에서 공용 로비와 2인 퀴즈를 직접 확인한 뒤, 로그인부터 퀴즈 결과까지 하나의 PR로 통합하도록 요청했다. #45, #47, #50, #51, #53의 커밋을 모았고 좌석 기록과 인원 표시를 `7fc4b9f`에서 수정했다. [이슈 #54](https://github.com/ghwls9896/CampusCommons/issues/54) · [통합 PR #55](https://github.com/ghwls9896/CampusCommons/pull/55)

이전 게임은 계정 확인 전 기기 공용 XML을 독점했다. 두 번째 실행에서는 저장소 열기가 실패해 로그인한 계정도 공부 기록을 시작할 수 없었다. 이제 로그인한 계정별로 파일 잠금을 획득하고 로그아웃이나 계정 전환 때 해제한다. 각 계정은 최초 사용 시 기존 공용 파일에서 자신의 미전송 세션과 합계만 승계한다. 같은 계정의 중복 쓰기는 계속 차단한다. 로비 인원은 좌측 상단에 배치하고 도서관 제목 영역과 겹치면 그 아래로 이동한다.

- Unity 6000.4.5f1 Play Mode에서 수정 전 공용 저장소의 로그인 전 점유와 기존 중앙 배치를 재현했다. 수정 후 공부 동기화, 로비 착석·타이머·로그아웃, 포커스 전환, 세 해상도 인원 위치, 원격 아바타, 계정 흐름과 퀴즈룸 통합 등 여섯 검사가 통과했다. 인증·공부 판정은 테스트 데이터를 사용했다. 에디터 검색 색인에서 기존 예외가 출력된 검사도 종료 코드 0과 완료 표식을 확인했다.
- Unity Mono 저장소 검사 15개에 별도 OS 프로세스의 동시 공부 시작·저장, 기동 순서 변경, 동일 계정 잠금, 기존 기록 승계·중복 방지가 포함된다. 시간 집계 13개, 백엔드 96개, 팀 검사 16개가 통과했다.
- 같은 Unity 버전으로 macOS ARM64 통합본을 빌드하고 서명 검증 후 A·B 두 로그인 화면을 확인했다. 보고된 오류 수정 후의 실카메라 측정, Windows 실기기, 실제 가입·복구 메일은 이번에 확인하지 않았다.
- 11월 19일 운영 Render에서 실제 두 계정의 PDF별 출제·채점을 확인했다. [서버 인계](cc-48.md)
- 공유 파일 `backend/app.py`와 `render.yaml`은 선행 PR에서 가져왔다. 리뷰 후속 변경은 두 공유 파일을 편집하지 않았다. 원본 PR 다섯 개는 #55로 대체해 닫았고, 브랜치는 병합 때까지 보관한다. #33은 보류한다.

## #55 리뷰 후속

- Unity는 착석 때 받은 계정 인증 만료 시각에 맞춰, 같은 계정의 갱신된 로그인 토큰과 기존 좌석 티켓으로 재인증한다. 서버는 기존 좌석·경기·답안·타이머를 유지한다.
- PDF 교체는 새 범위와 용량을 확인하고 현재 좌석·라운드를 다시 검사한 뒤 반영한다. 잘못된 교체는 이전 PDF 또는 이미 생성된 문제를 보존한다.
- Unity 빌드 검사는 예전 퀴즈 연결 파일이 Resources에 있으면 중단한다. [팀 개발 절차](../../README.md#팀-개발)와 [Windows 안내](../distribution/WINDOWS_TEAM.md)는 병합 후 최신 `main`을 Unity로 여는 흐름을 설명한다.
- 백엔드 99개와 팀 도구 16개가 통과했다. 서버 회귀 검사에서 갱신 전후 같은 라운드·답안·남은 시간, 잘못된 PDF 교체 후 재시도, 제3 계정의 양쪽 좌석 거절을 확인했다.
- Unity 6000.4.5f1 두 클라이언트에서 각각 로그인 토큰을 갱신해 같은 경기에서 개인 PDF 풀이와 결과까지 확인했다. 로컬 FastAPI를 사용했고 계정과 AI는 테스트 응답을 사용했다. Windows 실기기는 이번 검증 범위에 포함되지 않았다.
- Unity의 퀴즈룸·계정 통합 Play Mode 검사와 빌드 설정 검사도 통과했다. 검사 프로젝트에는 가짜 데이터의 예전 설정 파일을 가져와 빌드 차단을 확인하고, 제거한 뒤 다시 통과하는지 확인했다.
- ghwls9896 검토·병합 후 팀원은 최신 `main`을 받아 Unity에서 작업한다. 두 서버 수정이 실제 접속에도 적용되려면 새 백엔드 코드를 운영 Render에 배포해야 한다.
