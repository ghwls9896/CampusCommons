# Unity 도서관 공용 로비

게임에서 평소처럼 로그인하면 도서관 상단에 **공용 로비 1 / 8**이 표시된다. 다른 계정으로 로그인한 사람이 같은 서버의 도서관에 들어오면 인원수가 올라가고, 그 사람의 머리 위에 내 캐릭터와 같은 위치·글꼴로 닉네임과 레벨이 보인다. 별도 방 코드나 방장은 필요 없다.

| 게임에서 한 동작 | 다른 창에서 보이는 결과 |
|---|---|
| 도서관에서 걷기, 달리기, 멈추기 | 해당 캐릭터의 위치, 몸 방향, 움직임이 갱신된다. |
| 개인방 입장 | 도서관에서 캐릭터가 사라지고 인원수가 줄어든다. |
| 도서관으로 돌아오기 | 복귀한 위치에 캐릭터가 다시 나타난다. |
| 닉네임 또는 계정 레벨 변경 | 로비 연결이 갱신되고 서버가 계정에서 확인한 닉네임과 레벨이 보인다. |
| 로그아웃 또는 게임 종료 | 해당 캐릭터가 사라진다. |
| 같은 계정으로 두 번째 창에서 입장 | 새 창이 자리를 이어받고 첫 창에 중복 접속 안내가 뜬다. |
| 정원 8명이 찬 상태에서 입장 | 만원 안내가 뜨고 10초마다 빈자리를 다시 확인한다. |

## 운영 서버와 로컬 시연

일반 데스크톱 빌드는 `wss://campuscommons-quiz.onrender.com/v1/lobby/ws`에 접속한다. [서버 PR #45](https://github.com/ghwls9896/CampusCommons/pull/45)를 먼저 통합하고 기존 Render 서비스에 배포한다. 서버는 기존 게임과 같은 프로젝트의 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`로 계정 함수를 호출한다. 서비스가 휴면 상태면 연결 안내가 잠시 유지될 수 있다.

Mac 두 창 시연용 빌드는 컴파일 기호 `CAMPUS_LOBBY_LOCAL`로 같은 서버의 루프백 주소 `ws://127.0.0.1:18646/v1/lobby/ws`에 접속한다. Mac의 전용 실행 스크립트가 서버와 두 게임 창을 함께 연다. 로그인에는 인터넷 연결과 서로 다른 실제 게임 계정 두 개가 필요하다. 두 컴퓨터에서 시험할 때는 양쪽 모두 운영 주소를 사용하는 빌드를 실행한다.

## Unity 연결 경로

- 계정 프로필 준비가 끝나고 도서관의 로컬 Player가 활성화되면 LibraryLobby가 연결한다. 계정 테스트에서 대체 전송 계층을 주입할 때는 로비 통신을 명시적으로 켜야 한다.
- AccountSession이 현재 사용자를 확인하고 갱신한 액세스 토큰을 고정된 서버로 향하는 WebSocket 인증 헤더에 넣는다. 서버가 확인한 닉네임을 사용하며, Unity는 로비 참가자를 서버가 발급한 공개 ID로 구분한다.
- 첫 명단을 받으면 현재 자세를 보내고, 이후 변경된 위치·방향·걷기 상태를 초당 최대 10회 보낸다. 입장 중 입구에서 이미 걸어 나간 사용자는 현재 위치를 유지한다.
- 서버가 보낸 전체 명단에 따라 원격 아바타를 추가·보간·제거한다. 원격 캐릭터는 외형과 이동 애니메이션만 갖는다. 이름이 같은 두 계정도 서로 구분한다.
- 로그아웃·개인방 입장에서 진행 중인 연결을 취소한다. 일시적 단절은 2~30초 간격으로 재시도한다. 서버가 같은 계정의 새 연결로 교체한 창은 자동 접속을 중단한다.

## 에디터 회귀 검사

Unity 6000.4.5f1에서 `-batchmode -nographics -projectPath <프로젝트> -executeMethod CampusCommons.Multiplayer.LobbyAvatarVerification.Run -logFile <로그>`로 실행한다. 검사가 Play Mode에서 끝나면 에디터가 종료 코드를 반환한다. 테스트는 실제 도서관 씬에서 입장 슬롯, 같은 닉네임의 다른 참가자, 아직 위치가 없는 참가자, 로컬 전용 컴포넌트와 퇴장 처리를 확인한다. 계정과 네트워크가 없어도 이 검사를 실행할 수 있다.
