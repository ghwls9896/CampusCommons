# Desktop game distribution design

User request: Windows and macOS players download the game and use login, PDF quiz and webcam without manually installing Python/models or copying QuizConnection.json.

## Approach
Ship an offline, self-contained Python 3.12 + pinned QEV dependencies + model ZIP as Unity StreamingAssets. First launch verifies and extracts it into a versioned per-user writable directory on a worker thread; login/quiz remain available during preparation, webcam Start waits for readiness. No system Python/PATH/admin changes. Camera permission remains an OS prompt. QuizConnection.json and the public account configuration are embedded through their existing Resources paths; a build gate rejects missing configuration/payload. Quiz demo access code is confidential source configuration, not a Gemini key; embedding is authorized for the existing team demo, never commit its live value.

Alternatives: first-run online pip/model install has network/compiler/Git/dependency failure modes and requires hosting/version trust; asking players to install Python violates the request. All-in-one payload is selected as the implementation default; it increases download/disk size but needs no first-run network for setup.

## Platform boundary
Windows x86-64 and macOS 15+ Apple Silicon are the supported package targets. Windows uses CPU inference as a portable baseline; Apple Silicon uses existing MPS path. Existing pinned torch lacks modern Intel Mac wheels; do not claim Intel Mac compatibility. Packaging runs natively on each OS to resolve native dependencies. Current machine can build/test Mac; Windows tooling must be provided and its missing native validation reported honestly. No signed/notarized store release is implied.

## Components/contract
- Tools/distribution/prepare_runtime.py: uv managed CPython3.12.11, isolated payload/python, pinned pip dependencies, app source, pinned model/cache, notices. Optional existing model cache is copied without symlinks. Probe relocated payload with sanitized environment. Produce payload.zip and manifest.json in Assets/StreamingAssets/StudyRuntime; generated payloads ignored by Git.
- Manifest schema1: platform (macos-arm64/windows-x64), archive=payload.zip, sha256 (lowercase64), archiveBytes, unpackedBytes, python relative path (python/bin/python3.12 or python/python.exe), executablePaths array, minimumOS (15.0 for macOS). SHA also names immutable install version. ZIP paths are relative, regular files/directories only, no symlinks, no traversal/case aliases. ZIP64 supported.
- Pure C# RuntimePackageInstaller validates descriptor/archive, extracts safely with size limits into a staging directory under an exclusive per-package lock (native flock on Mono/macOS), protects active Python users with shared lifetime leases, restores executable modes on Mac, atomically renames after success, writes readiness marker last. Cancellation/error never yields ready; retry cleans only its own staging. Verify installed entrypoints and archive digest marker on subsequent launch. Failure UI offers retry and does not block login/quiz.
- StudyRuntimeBootstrap MonoBehaviour installs on first scene, reports percent/status, observes task errors, cancels on quit, caches selected root. Editor may use existing development runtime when no payload is staged; standalone never relies on a developer path. LocalStudyProcess uses bootstrap runtime root/python, sanitized PYTHONHOME/PYTHONPATH/user site, existing offline model flags.
- DistributionBuild preflight validates account/quiz settings and matching payload/target; exposes MacARM64 and Windows64 build commands and includes camera permission hook. Target-specific output, only actual GrandLibrary_Living startup scene. Build secrets may come from local ignored file or environment, never diagnostics. Scripts for developer build preparation; players only launch the game.

## Verification
Pure C# extraction tests: fresh/cache/retry, checksum corruption, traversal/backslash/absolute/symlink/case collision, oversize, cancellation, correct platform, executable restore, spaces/unicode, concurrent installers. Python package tests: layout/platform validation and copied-cache layout. Native Mac moved-runtime smoke imports + QEV offline model load; Unity batch compile/bootstrap fixture and existing quiz/account/webcam checks. Actual Mac standalone build fresh install with existing developer runtime unavailable via bootstrap override and verify child Python origin. Windows tests/build require Windows host; no success claim without evidence. Preserve existing Sunbox assets and shared scenes.
