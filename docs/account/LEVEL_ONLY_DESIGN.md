# 계정 레벨 1~15 — 2026-11-12 승인 범위

사용자가 로그인·회원가입 마무리와 계정별 Lv.1~15 저장·조회를 요청했다. 경험치 상승·재화는 추후 구현한다. 5/10/15레벨 외형 아이템은 향후 계획이며 이번에는 지급하지 않는다.

## 설계
- 기존 계정 기능 브랜치/PR #10을 계속 사용한다. 공유 게임 스크립트·씬·Unity 버전은 수정하지 않는다.
- player_progress.level을 XP generated 열에서 독립적인 NOT NULL 정수로 전환한다. 기본1, CHECK 1~15. 기존 레벨/XP/이벤트를 보존한다. 범위 밖 기존 레벨이 있으면 migration을 중단하며 임의로 낮추지 않는다.
- 계정 API 응답은 {user_id,nickname,level}. Unity는 소유자와 범위1~15를 검증하며 닉네임 변경·재로그인으로 레벨이 초기화되지 않는다. UI는 닉네임·레벨만 표시한다.
- 레벨 변경은 신뢰된 DB 관리자/서버만 가능. 클라이언트 쓰기와 임의 level 요청은 거절. 관리자 웹 화면이나 공개 레벨 변경 API는 만들지 않는다.
- 기존 XP 값·이력은 보존하되 progression endpoint와 DB 보상 함수 모두 지급을 거절한다. 환경변수로 우연히 재활성화되지 않는다.
- 이메일/비밀번호, 가입/복구 OTP, 재전송, 새 비밀번호, 닉네임, 세션/로그아웃을 유지하고 성공·실패/계정 전환 경로를 검증한다. 복구 세션은 비밀번호 변경 전에 게임에 입장할 수 없다.

## 선택한 접근
XP 공식을 유지하며 화면만 숨기는 방식은 레벨 저장이 XP에 계속 종속된다. 별도 중복 레벨 테이블은 권한·동기화를 늘린다. 기존 level 열을 데이터 보존 방식으로 전환하는 안을 사용자가 선택했고 구현을 요청했다.

## 배포·검증
새 migration → 두 Edge 함수 배포 → 새 Unity 클라이언트 사용. 이전 클라이언트는 XP 필드를 요구하므로 업데이트가 필요하다. PostgreSQL 역할/RLS·레벨 경계·기존 데이터 보존, Deno API, C# 세션, 임시 Unity6000.6 실제 씬을 검사한다. 지정6000.4.5 미설치와 실제 메일 검증 범위는 명확히 기록한다. 신뢰된 서버 테스트와 실제 사용자 비밀번호 입력은 구분한다.
